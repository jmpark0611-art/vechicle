# 데모 동등성 기준

이 프로젝트의 테스트 기준은 `Vehicle system UI improvement.zip` 안의 `차량운행시스템.dc.html`이다.
APK 화면과 기능은 이 데모와 같은 흐름으로 테스트 가능해야 한다.

## 기준 원칙

- 과거 다크+라임 UI는 기준에서 제외한다.
- 기본 UI는 라이트 배경, 흰 카드, 딥블루 포인트를 사용한다.
- 데모의 예시값은 실제 앱에서 DB/GPS/OBD 데이터로 대체하되, 화면 위치와 조작 흐름은 유지한다.
- 데모 HTML을 그대로 복사하지 않고 Expo React Native 구조로 재구현한다.
- 새 작업은 `claude/env-permissions-session-restart-154onb` 브랜치에서 이어간다.

## 탭별 동등성 체크리스트

### 역할 선택

- 중앙 앱 로고 표시
- `차량관리시스템` 제목과 `모드를 선택하세요` 문구 표시
- `운행 모드` 카드: 운전자/운용자용, 운행 시작/종료
- `수송부 모드` 카드: 관리자용, 기록/차량 진단/위치 관리
- 테마 선택 점 3개 표시

### 운행

- 제목은 `운행`
- 상단에 `수송부 모드로 전환` 버튼 표시
- 대기 화면 순서:
  1. 차량 선택
  2. 운행 정보
  3. 경로
  4. 출발 버튼
- 운행 정보에는 운용자 성명, 사용자 성명, 운행 목적 입력이 있어야 한다.
- 경로에는 출발지, 목적지 입력이 있어야 한다.
- 운용자/사용자 성명이 없으면 출발할 수 없어야 한다.
- 운행 중 화면은 히어로 카드로 속도, 경과, 경로, 출발시각을 보여야 한다.
- 운행 종료 시 일일km, 누적km, 유류, 비고 입력 흐름이 있어야 한다.

### 기록

- 제목은 `운행 기록`
- CSV 버튼 표시
- `카드형`/`리스트형` 토글 표시
- 필터 칩: 전체, 운행중, 완료
- 카드형 기록에는 차량번호, 상태, 출발/도착, 시간, 주행거리, 누적거리, 유류사용, 운용자/사용자 정보가 보여야 한다.
- 리스트형 기록에는 시간, 차량번호, 운전자/사용자, 출발→도착, 주행거리가 한 줄 구조로 보여야 한다.

### 차량

- 제목은 `차량 진단`
- `등록` 버튼 표시
- 차량 선택 칩 또는 드롭다운 표시
- OBD 스캐너 상태 카드 표시
- ECU 실시간 데이터 표시: 냉각수 온도, 배터리 전압, 엔진 회전수, 연료 잔량, 흡기 온도, 주행 가능 또는 엔진 부하
- 고장코드(DTC) 상태 표시
- 소모품 교환주기 진행 막대 표시
- OBD 단말기 연결은 `/obd` 화면에서 처리한다.

### 위치

- 제목은 `실시간 위치`
- 운행 중 차량 수와 실시간 갱신 상태 표시
- 지도 영역 표시
- 운행 중 차량 리스트 표시
- 차량별 상태: 정상/경보, 최근 GPS 시간 표시

## 현재 완료 상태

- 역할 선택: 1차 반영 완료
- 운행 대기 화면: 1차 반영 완료
- 운행 중 히어로 카드: 다른 AI의 `25ef841`에서 1차 반영됨
- OBD 연결 패키지와 `/obd` 화면: 브랜치에 존재
- 기록/차량/위치: 기능은 일부 존재하지만 데모와 픽셀/구조 동등성은 추가 정리 필요
